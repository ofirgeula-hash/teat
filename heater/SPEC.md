# דוד — אפיון (גרסה 2)

אפליקציית PWA אישית (עברית, RTL, ערכת צבעים כהה, מותאמת לטלפון) לשליטה מרחוק בדוד המים
דרך מתג Tuya קיים. חינמית לגמרי, משתמש אחד, ובלי חומרה נוספת.

## החלטות
| נושא | החלטה |
|---|---|
| חיבור למתג | ענן Tuya, דרך ה-OpenAPI הרשמי. קישור SmartLife נעשה פעם אחת, כהרשאה |
| המתג | לא נוגעים בו פיזית. מניחים שהוא מתאים לעומס, כי הוא עובד שנים. נציג את פרטי הדגם מה-API לצורך מידע בלבד |
| אינטרנט בבית | מניחים שהוא תקין תמיד |
| אירוח | Cloudflare Workers (בחינם): שרת, קבצים סטטיים, Durable Object ‏(SQLite) ו-Cron |
| אחסון | Durable Object עם SQLite. לא KV, כי ב-KV החינמי מותרות רק כ-1,000 כתיבות ביום |
| הבנייה | שכבת "נהג" (driver) נפרדת לגישה ל-Tuya, כדי שהאפליקציה לא תהיה קשורה אליה |

## מכשיר
- device_id: `bf04b2937822abd88csdi9`
- בעלייה, השרת קורא את המפרט והמצב של המכשיר מ-Tuya ומשתמש בקודי הפונקציות האמיתיים, בלי ערכים קבועים בקוד.
  צפויים: `switch_1`, ‏`countdown_1`, ואולי גם `switch_inching` / `relay_status`.
- דף "על המכשיר": שם המוצר וקטגוריה מה-API, הפונקציות הנתמכות, ומצב חיבור (online).

## בטיחות (הדבר הכי חשוב)
1. **טיימר בתוך המתג:** כל פקודת הדלקה, מהאפליקציה או מתזמון, נשלחת יחד עם
   `countdown_1 = min(משך מבוקש, זמן מקסימלי)`. כך המתג יכבה את עצמו גם אם השרת לא זמין.
   אם `countdown_1` לא נתמך, מוצגת אזהרה קבועה, וההגנה תלויה בשרת בלבד.
2. **מגבלה גם להדלקה ידנית:** אם יש `switch_inching`, מגדירים אותו לזמן המקסימלי (אם הטווח שלו מאפשר),
   כדי שהמתג יגביל גם הדלקה מהקיר או מ-SmartLife. אם הוא לא קיים, ההגבלה תלויה בשרת בלבד.
3. **מגבלה בשרת:** Cron כל דקה בודק את המצב וזוכר ממתי המתג דלוק. אחרי הזמן המקסימלי הוא מכבה,
   לא משנה מי הדליק (אפליקציה, תזמון, קיר או SmartLife).
4. **כיבוי מדויק:** Durable Object alarm מוגדר לזמן הכיבוי המדויק. ה-Cron הוא רק גיבוי.
5. **סנכרון וניסיונות חוזרים:** ה-Cron משווה בין המצב הרצוי למצב בפועל, מריץ תזמונים שהגיע זמנם,
   ומנסה שוב כש-Tuya מחזירה שגיאה (המתנה הולכת וגדלה בין ניסיונות).
6. **כשל בכיבוי:** ניסיונות חוזרים, אזהרה בולטת באפליקציה והתראת Push.
7. רענון אוטומטי של הטוקן של Tuya, שנשמר במטמון עד שתוקפו פג.

## מסכים
1. **ראשי:** כפתור ON/OFF ענק שמציג את המצב האמיתי. המצב מתעדכן בפתיחה וכל כמה שניות כשהאפליקציה גלויה.
   כשהדוד דלוק יש ספירה לאחור עד הכיבוי, ומתחת שישה כפתורי טיימר מהיר:
   15 / 30 / 45 / 60 / 90 / "מקסימום (90 דק')".
2. **תזמונים:** כללים עם ימים בשבוע, שעת התחלה, משך או שעת סיום, ומתג הפעלה. אפשר להוסיף, לערוך ולמחוק.
   אזור הזמן הוא Asia/Jerusalem.
3. **היסטוריה:** 50 הפעולות האחרונות, עם המקור (אפליקציה / תזמון / ידני / כיבוי בטיחות) ותוצאה.
   "ידני" = שינוי מצב שלא נגרם מהשרת.
4. **הגדרות:** זמן מקסימלי רציף (ברירת מחדל 90 דקות), ערכי הטיימרים המהירים, ניהול Passkeys,
   החלפת סיסמה והתראות Push.
5. **מצבים ברורים:** המתג לא מחובר, שגיאת Tuya, ההתחברות פגה, הטיימר במתג לא נתמך, כשל בכיבוי.

## כניסה ואבטחה
- כניסה ראשית עם Passkey ‏(Face ID), וסיסמה כגיבוי (PBKDF2 עם salt).
- Session cookie מסוג HttpOnly + Secure + SameSite=Strict, ובדיקת Origin בכל פעולה שמשנה משהו.
- הגבלת ניסיונות כניסה (עם השהיה שהולכת וגדלה, לפי IP ובאופן כללי).
- הסודות של Tuya נשמרים רק כ-Worker secrets.

## התראות Push
Web Push עם VAPID (עובד ב-iOS 16.4 ומעלה, לאפליקציה שמותקנת במסך הבית). נשלחת התראה על: כשל בכיבוי,
כיבוי בטיחות, המתג לא מחובר כשמתזמון אמור לפעול, ו-Tuya API שלא זמין לאורך זמן.

## SmartLife
הוא נשאר רק כ"בעלים" של המתג בענן של Tuya. אין צורך לפתוח אותו, והוא משמש כשליטת גיבוי.
- **לא** למחוק את חשבון SmartLife ו**לא** להסיר ממנו את המתג. זה ינתק את הגישה של הפרויקט.
- למחוק טיימרים ואוטומציות של המתג בתוך SmartLife, כדי שלא יתנגשו עם האפליקציה.

## מגבלות חינמיות שצריך לבדוק
- Tuya: המכסה החודשית של תקופת הניסיון וחידוש התקופה (יתועד ב-README).
- Cloudflare Workers Free: ‏100 אלף בקשות ביום, Cron, ו-Durable Objects עם SQLite. בשימוש הזה רחוק מהגבולות.
